# Product Decisions

## Scope and Safety

- All project files live in the Parallax workspace. Reference projects were read only. No environment file was opened, copied, or used as a template; only placeholder `.env.example` files were created. No wallet private key is held by the application.
- Trading is hard-coded disabled in `config.ts`; `/trade` always returns 403. There is no hidden enable switch or order SDK dependency. No signing, simulation, builder registration, collateral transfer, or order placement was exercised.
- Velocity documentation identifies SDK version 0.27.0, but the SDK is intentionally not installed because signing/execution has not been safely validated. Public data access does not establish the correctness of a transaction integration.
- Velocity is cross-margin **within a subaccount**, not isolated margin. Mainnet collateral is USDT; devnet collateral is dUSDT. A devnet execution preference does not turn the public market data feed into a devnet quote source. Current public Velocity market quotes identify USDT.
- Builder fees are denominated in tenths of a basis point. Protocol ceiling: 1,000; stricter application ceiling: 100; default: 20 (2 bps). Clamp math is tested, but no builder fee is charged because execution is disabled.
- Country headers are not trusted on the directly bound development API. Unknown/untrusted country is denied for execution, even if a client submits `cf-ipcountry`. A future deployment must authenticate its proxy and replace this deny-all gate before considering execution. A valid country is not legal or trading authorization.

## Provenance

Velocity `/stats/markets` was called live with certificate verification. The response mixes spot and perpetual markets. The parser selects active perpetuals and uses discovered `marketIndex`, symbols, collateral, prices, volume and signed open interest. Funding strings are displayed as raw source values because their interval/unit is undocumented. No APR or APY is inferred.

The direct Gamma markets endpoint responded to a verified TLS HEAD request with HTTP 200 and a deprecation warning directing clients to `/markets/keyset`. A subsequent verified TLS GET to `/markets/keyset?limit=1&active=true&closed=false` returned HTTP 200 with actual market records. The worker now probes that current endpoint, independently of Jupiter ingestion. Earlier connection problems do not justify a blanket claim that Gamma is down. Gamma is a transport to Polymarket, not a second prediction venue.

An early direct Kalshi curl attempt failed to connect. Subsequent verified TLS GETs succeeded with HTTP 200 and actual market records at both `https://api.elections.kalshi.com/trade-api/v2/markets?limit=1&status=open` and the originally requested `https://external-api.kalshi.com/trade-api/v2/markets?limit=1&status=open`. TLS verification was never disabled. The worker probes both hosts and reports current results rather than asserting that the earlier failure is permanent. Jupiter's documented `provider=kalshi&filter=trending&includeMarkets=true&category=crypto&start=0&end=2` returned HTTP 200 with `data: []`. That query's missing crypto coverage is distinct from direct API availability. No Kalshi contract has been reviewed and matched for the terminal yet, so its aggregate health remains degraded even when public connectivity is healthy.

Jupiter events document a `kalshi` provider filter, while the Market provider enum includes `polymarket`, `gx`, and `bisonfi`. `gx` has not been proven equivalent to Kalshi. The parser excludes it. Polymarket provenance remains `venue: 'polymarket'`, `transport: 'jupiter'`. No transport is used to inflate venue count or consensus weight.

Jupiter's documented single-market price unit is microUSD. YES ask is `buyYesPriceUsd / 1e6`, YES bid is `sellYesPriceUsd / 1e6`. Mid requires both sides and a non-crossed book. Closed contracts have null quotes. Source pricing `volume` is not documented as a rolling 24-hour value, so it is not mislabeled as `volume24h`. Event-level `volume24hr` is microUSD but is not attributable to each strike. Missing market volume/liquidity remains null.

## Human Review

Forty-three distinct single-market rule sets were individually read, not just event titles. Thirty-nine were open and four were closed at detail review. Nineteen additional BTC/SOL contracts were re-fetched individually and matched the preserved evidence in `src/data/reviewed.ts`, including rule text, title, expiry, and creation timestamp. The manifest retains each opaque provider market ID, exact title/strike, expiry, SHA-256 normalized rule hash, direction, mapping, status, and reason; creation timestamps are additionally pinned where present in the evidence. Full current rules are stored in PostgreSQL and displayed by the API/CLI. All IDs and review reasons are checked in; no ephemeral tool-output path is a runtime dependency.

Thirty-two open contracts have direct BTC/SOL/ETH directional research relationships. Several share an event but have distinct strikes and/or windows; they are not 32 independent macro narratives or cross-venue pairs. Seven remain candidates: FDV/launch/sale/political contracts lack a defensible discovered underlying, and the BTC interval contract is non-monotonic. Four short-duration Chainlink-TWAP contracts were rejected after the detail endpoint revealed they were already closed. They remain visible as rejected reviews, with null quotes, rather than being silently erased or counted as live.

An approved mapping means a reviewed directional research relationship, not identical economic exposure or matched settlement. Binance highs/lows, strict noon closes, Chainlink TWAP, start-of-month versus creation-time windows, exact strikes, ET timezone, source, and expiry distinctions are preserved. Downside contracts use direction -1 so their NO outcome is oriented toward a bullish perp comparison. No fake Kalshi match was created to satisfy a cross-venue count.

`confidence` is an explicit review heuristic (0.8 approved; 0.15 candidate/rejected), not a calibrated probability, statistical model result, or expected return. Each theme currently has exactly one contract. The database can represent mappings, but multi-contract equivalence is intentionally not seeded or approved by the CLI. Any future equivalence group requires a contract-specific reviewed key plus matching source/rules and expiry. Related event strikes are not averaged together.

## Persistence and Signals

PostgreSQL stores venues, markets, themes, mapping/review audit, prediction/perp snapshots, signals, users, nonces, sessions, watchlists, alerts/deliveries, disabled execution intents/audit, venue health, worker state, and schema version. Migration startup uses a PostgreSQL advisory lock and a transaction. Compose is infrastructure only; API/worker run through workspace scripts.

Redis stores five-second terminal and thirty-second candle caches, distributed request-rate state, a renewable ingestion lease, and feed pub/sub. Jupiter calls, including retries and review CLI calls, acquire one global 2.2-second slot. No API key is needed or loaded. Network calls time out, reject redirects, retry bounded 429/5xx/network errors with backoff, and never disable certificate validation. Redis loss prevents new Jupiter requests rather than dropping the global rate limit.

Only actual samples appear in history. Failed ingestion retains old samples with original timestamps and degraded venue health. On every terminal response, including Redis cache hits, prediction bid/ask/mid are nulled if their source capture is over five minutes old, future-dated or invalid, if the contract has expired, or if its theme is rejected. This works even if the worker has stopped. Source and terminal `capturedAt` values are never rewritten to pretend that stale data is fresh. Historical samples are not erased. Perp marks remain non-null under the fixed shared contract, retain their source timestamps, and must not be interpreted as executable live quotes; stale venue health is also re-evaluated on every response. No synthetic production data or retrospective prediction history is inserted. Seven-day history is a trailing window of accumulated samples, not a promise that a fresh database already has seven days of data.

Divergence is computed only for currently approved single-contract perp mappings. The default window W is **60 minutes**, configurable through `SIGNAL_WINDOW_MINUTES`; the z threshold defaults to 2, follow threshold to 0.5, and minimum historical comparison count to 30. It uses a backward-only as-of join (at most five minutes old), probability deltas versus log perp returns, and non-overlapping W-minute baseline comparisons in the preceding seven days. Baseline windows end strictly before the current comparison starts. Future, stale, duplicate, out-of-window and degenerate-variance observations cannot generate a signal. No seven-day data is fabricated to bypass warmup.

The shared `measureLead` helper accepts raw YES probabilities and direction d. Standardize each current W-minute change using its own historical mean and sample standard deviation to obtain zP and zR. The exact mirrored formulas are:

```text
oddsFollower = sign(rawProbabilityDelta) * d * zR
perpFollower = sign(rawPerpLogReturn) * d * zP
ODDS_LEAD: rawProbabilityDelta != 0 AND abs(zP) >= zThreshold AND oddsFollower < followThreshold
PERP_LEAD: rawPerpLogReturn != 0 AND abs(zR) >= zThreshold AND perpFollower < followThreshold
divergence = abs(leaderZ) - projectedFollowerZ
```

The follower is a signed projection onto the leader's actual observed movement, not the sign of its mean-centered z-score: a positive raw change can have a negative z-score when the historical mean is positive. Regression tests cover that sign reversal for both mirrored cases and suppress zero-change leaders even when a nonzero baseline mean would produce a large z-score. An opposite-direction response is non-following. If both tests qualify, the larger absolute standardized leader wins; exact ties suppress the ambiguous result. Production history already orients downside NO probability toward bullish perps, so its call to the helper uses d=1 and does not invert twice. `ODDS_LEAD`/`PERP_LEAD` are descriptive statistical classifications, not causal leadership, a validated predictive model, or recommendations.

Executable spread helpers use ask-to-buy and bid-to-sell, correctly invert NO (`bid=1-yesAsk`, `ask=1-yesBid`), and subtract nonnegative fee cost. They are not exposed as an executable arbitrage opportunity: there are no reviewed independent-venue equivalents in the current manifest. Consensus first deduplicates venue/contract identity, keeping the first canonical supplied record rather than counting transports separately. A single contract retains its valid oriented midpoint even without liquidity. A multi-contract reviewed group weights only valid midpoints with known finite positive liquidity; unknown, zero, negative and nonfinite weights are excluded. If none have a usable weight, consensus is null, not an invented equal-weight average. When only a subset has verified weights, the result covers that subset only, not a claim of complete venue coverage. Scaling weights avoids overflow. Multi-contract probability history is suppressed until reviewed, time-aligned historical liquidity weights are implemented; the current single-contract histories are unchanged.

`rulesDiff` provides conservative review diagnostics for close-time gaps strictly greater than 24 hours (exactly 24 is not that flag), unknown close times, differing/unknown named sources, differing/unknown numeric barriers, and declared/arrow outcome orientation. Numeric barriers normalize commas, decimals and K/M/B suffixes. Names and URLs mentioned in rules are textual evidence, not proof that the full settlement semantics match. Unrecognized or ambiguous rules still require manual review. `inspect` prints these flags against the last stored contract. The separate equivalence gate remains stricter: explicit reviewed key, exact title, exact expiry, matching orientation and identical normalized rule text are all required. A lack of heuristic flags is never automatic approval or cross-venue equivalence.

## Authentication and Alerts

SIWS-style text binds public wallet, exact browser domain/URI, cluster preference, random nonce, issued time, and five-minute expiration. Detached Ed25519 verification happens against the stored message. Nonce consumption and session creation are transactional; parallel replay cannot create a second session. Session tokens persist only as hashes. Nonce lookup keys are hashed, while the original public challenge message (including its nonce) is retained for signature verification until cleanup. Session cookies are HttpOnly, SameSite Strict, and Secure with a `__Host-` prefix in production; production requires HTTPS origin.

There is no server wallet key. Authentication-signature tests generate ephemeral keys only in tests; they do not exercise SDK transaction signing. Cookie-authenticated writes require exact Origin checks. CORS allows one explicit origin; WebSocket upgrades require that origin too. Request bodies are bounded, inputs are strict Zod schemas, rates are Redis-backed, CSP is restrictive, and logs redact cookies/signatures and omit upstream connection details.

Watchlists and threshold alerts are persisted per wallet. The worker records an in-app notice at most once an hour per alert when a fresh single-market oriented midpoint is at or above its threshold. This is a periodic threshold notice, not an exact price-crossing guarantee. Disabled alerts remain auditable. Telegram is disabled and no token is read; Telegram account linking and outbound delivery are not implemented.

## Remaining Limits

- No executed order test, transaction simulation, signing UX, builder fee verification on-chain, funding settlement reconciliation, or liquidation workflow was completed. Do not present this as trading-ready.
- No verified Kalshi crypto contract or reviewed independent-venue equivalent is seeded. A two-venue spread/consensus screen must honestly show insufficient independent sources.
- History and predictive-quality claims require real elapsed collection time; no historical odds backfill was verified.
- Research wallet sign-in, watchlists, threshold alert rules, disable actions, and recent in-app notices are wired to the frontend. Real wallet-extension signing has not been exercised; ephemeral signature tests verify the backend, not a complete wallet-extension flow. Email, Telegram transport, and account recovery are not implemented.
- Redis pub/sub is invalidation, not a durable stream. Browsers should refetch on connection/reconnection and periodically; events can be missed during disconnects.
- API/shared lint now runs actual ESLint and TypeScript syntax parsing with the existing workspace lint toolchain, without another install. The explicit resolver relies on the web workspace's installed `eslint`/`eslint-config-next` toolchain; standalone API-only packaging would need its own declared lint dependencies. Production authentication penetration testing, distributed failover, data retention/pruning policies, and load tests remain future work.

## Observatory Interface (Initial Revision)

- The interface follows the agreed Observatory direction: dark olive/charcoal surfaces, one acid-lime accent, local Manrope and JetBrains Mono fonts, restrained linework, a split event/perp relationship view, and no decorative fake quotes or signals. The requested `frontend-design` skill was not available in this session.
- Next.js 16.4.0 was selected from the locally verified toolchain after a 16.4.3 tarball download failed. Its installed `node_modules/next/dist/docs` installation, page, and Route Handler guides were read before Next code was written. Dependencies are pinned in the workspace lockfile.
- The web app provides `/`, `/t/[slug]`, `/markets`, `/signals`, `/portfolio`, `/alerts`, and draft `/legal/terms`, `/legal/risk`, `/legal/privacy`. It runs on `http://127.0.0.1:3100`, not `localhost`, to preserve exact-origin session and WebSocket checks. Another pre-existing IPv6 service uses the same port; it was not modified or stopped.
- Event probability and perp trade-close history use independent price scales and a shared actual 24-hour/seven-day time window. Seven-day axes include dates. No probability backfill or invented trend line is used. A crosshair reports the nearest actual candle. Current mark, oracle, base-unit long/short open interest, and unconverted funding source strings remain distinct.
- Multiple contracts from an event are not averaged into a narrative consensus. The featured contract is an approved mapping with available mid probability, not a fabricated active divergence. Mapping heuristic confidence is not marketed as signal accuracy.
- Table sorting includes quote width, YES mid, expiry and review state; it does not label bid/ask width as cross-venue spread. Unknown per-contract volume/liquidity remains missing, so volume ranking cannot currently provide meaningful ordering. Mobile tables prioritize event and probability, with full context on the detail page.
- A trade-reference calculator supports side, market/limit reference, size, slippage input, notional and builder-fee arithmetic. It is not an executable quote, does not calculate verified protocol/network fees, and cannot request a transaction signature. No approval, leverage control, deposit, close-position, cancellation or order execution is claimed. The portfolio page explicitly says onchain subaccount/position reconciliation is unavailable, not that the wallet has zero positions.
- Candidate mappings are visibly unreviewed and do not claim a bullish/bearish relationship. Missing Kalshi equivalence shows unknown risk, not a false low-risk result. There is no claim of cross-venue arbitrage.
- The browser uses Solana Wallet Standard discovery with explicit message-signing consent. Mainnet-beta configuration is represented as `mainnet` in the SIWS message, per the supported sign-in specification. A research session does not authorize an order. Signing UI tests cover dialog behavior only, not a funded wallet.
- The same-origin web API proxy uses a fixed backend base, path allowlist, request size limit and exact-Origin write checks. It never trusts a browser-supplied client-IP/country header. Public read and write budgets are separate (600 reads, 120 writes per minute per direct IP), with independent ten-per-minute challenge/verify groups. Because proxy requests share a direct IP, a production deployment needs an authenticated edge/client identity and a reviewed abuse budget rather than blindly trusting forwarding headers.
- Browser CSP permits inline scripts/styles required by this static Next build; `unsafe-eval` is limited to development for React debugging. Production has no `unsafe-eval`. CSP nonce/hash hardening, hosting WSS configuration, and commercial-data permissions are launch prerequisites, not silently completed compliance gates.
- Telegram cannot be enabled simply by setting a token: linking and delivery must still be implemented. An optional LLM summary provider is omitted; rule text, diagnostics, and the application work without one. External public WebSocket ingestion is not implemented: workers poll conservatively, while the application WebSocket carries Redis-backed invalidation.

## Owner Prerequisites

The original Hyperliquid 100-USDC builder requirement and `HL_BUILDER_ADDRESS` do not apply to this Solana build. Before any execution feature is enabled, the owner must review Velocity's current terms, builder setup and collateral requirements, supply a funded devnet wallet through their own wallet UI, and verify the implemented approval/order/cancel flow. That flow is not implemented yet. Review theme mappings and all venue/data-use terms; commission legal review of the drafts. ## Signal Station (Previous Revision)

The user approved a more expressive retro-futurist direction after reviewing Theorem. This supersedes the initial olive/sidebar design, not its data or execution safety decisions. Theorem's live homepage/stylesheet and local reference source were read without changing that project. The result borrows tactile material contrast and a coherent interaction world, not coin-launch mechanics, pixel branding, fabricated market data, or gamified exposure.

- Global navigation replaces the sidebar. Midnight navy surrounds warm cream observation plates and analysis panels; cyan event odds and amber perp close prices remain separately labeled and independently scaled.
- The dual-channel receiver selects actual approved contract IDs using a native range input, previous/next controls, keyboard arrows, and plates. Filters cover all reviewed events, watched events and linked assets. An empty watchlist produces a standby screen, never a demo signal. The current selection is announced accessibly.
- Observation plates group reviewed contracts by linked asset, not a fabricated volume ranking. Each shows the actual YES midpoint, related mark, source provenance and close date. The segmented meter approximates the displayed YES midpoint and is decorative to assistive technology. Selecting a plate focuses the receiver; inspecting it opens the existing theme route. The table remains available for dense scanning.
- Pointer-responsive geometry is confined to decorative field points, bezel depth and observation plates. It does not encode correlation, liquidity, confidence or profit. The actual financial chart is not tilted. The canvas pauses when the document is hidden, draws statically for coarse pointers/reduced motion, and cleans up listeners/animation frames on unmount.
- Optional synthesized tuning ticks require an explicit user toggle, default off, and a subsequent tuning gesture. There is no autoplay audio, order celebration, trade score, external sound request or extra permission. The audio context is closed when the station unmounts.
- Forms, fees, risk disclosures and reference controls stay flat and stable. This visual revision adds no transaction permission, private-key handling, blockchain execution, Telegram delivery, calibrated prediction score or Kalshi equivalence claim.
- Installed Next.js server/client guidance was read before the revision. No new dependencies, provider endpoints, identifiers or environment variables were needed. Development mode remains on the existing project ports; no unrelated process was stopped.

## The Rift (Current Revision)

The owner rejected visual similarity to Theorem and then approved a larger surreal landscape theme. The Rift replaces the Station presentation rather than recoloring it: no navy/cream/yellow language, hardware receiver, enamel plates, dial, pixel treatment, hard shadows, or synthesized sounds remain. The obsolete Station component and stylesheets were removed. The existing API, financial calculations, wallet research permissions and execution locks were not changed.

- A procedural Three.js landscape contains two asymmetrical hanging basalt landforms, mineral seams, small suspended fragments, contrasting rim lights and an ember-lit chasm. Geometry, surface noise and fallback artwork are generated locally; no external model, image or texture service is used.
- `three` and `@types/three` are pinned at 0.187.0, verified from npm in this session. Official Three documentation and the installed Next.js client/server guide were read. A narrow pnpm release-age exception applies to the newly published matching type package, not to all dependencies.
- The scene is client-initialized through a dynamic library import. The SVG illustration is present at first paint and remains on import failure, unavailable WebGL, shader failure or lost context. Default Chrome desktop/mobile tests assert actual WebGL rendering, not merely that a canvas element exists.
- Mouse drag is bounded. Belief/reaction buttons change artistic focus; reset and pause are explicit. Touch scrolling remains native. Coarse pointers and reduced-motion settings use stable renders instead of ambient motion. Rendering pauses when hidden or offscreen, is capped at 30 FPS and DPR 1.5 desktop/1.2 mobile, and cleans up observers, listeners, geometries, textures, materials and renderer resources on unmount.
- Drawing buffers are retained so paused scenes remain visible. Unchanged dimensions do not clear the buffer; real resizes show the fallback until the next successful frame. Browser tests inspect nontransparent framebuffer pixels after pause/reset and scrolling, in addition to screenshots. This trades a bounded retained surface for reliable static/offscreen presentation.
- Scene geometry and cosmetic lighting do not encode market performance, liquidity, confidence, divergence or returns. A small selection-key variation is aesthetic only. The visible artwork disclaimer says it is not a financial model. The financial annotations are separate DOM elements bound to actual source quotes and retain unavailable states.
- The event atlas replaces plates with a quiet, searchable editorial index. Selection updates the visible event, its real probability, linked perp and source annotations. Watchlist and asset filtering, previous/next, keyboard selection, inspection links and a table alternative remain functional. Selecting a contract never requests a wallet transaction signature.
- Artwork still renders during an API outage, but no quote, contract, price history or signal is substituted. Real history remains in a separate analysis section with independent scales. Research and execution forms stay visually stable.
- The visual regression suite now checks actual available reviewed data rather than requiring the historical seed to remain unexpired forever. Original coverage is not claimed by that test: the live call during this revision returned 16 approved contracts after natural expiries. Expanding/re-reviewing current coverage is a distinct remaining requirement; no review status was altered to satisfy a UI test.
